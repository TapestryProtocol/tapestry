# Issue Evaluator verdict format — v1

What a verdict looks like on an ngit issue, and in the judge's answer. The judge, `/evaluate-issues`, the night session and the Loom page all read this file. The rules behind a verdict are in [rubric.md](rubric.md).

## Labels

`ready-to-one-shot` and `not-ready-to-one-shot`: NIP-32 label events (kind 1985, `#t` namespace) that point at the issue, as `ngit issue label` makes them. ngit accepts a label only from the issue's author or a repo maintainer, and has no way to remove one. **The verdict of record is the newer of the two labels**, among those from the author or a maintainer. ngit's own list shows both after a flip, so a reader that needs the verdict reads the label events' times.

## Comments

Every verdict is a comment, posted just before its label. Its first line is the marker:

```
> **Issue Evaluator** · generated by AI · rubric v1 · judged against `<ref>` @ `<sha8>`
```

`<ref>` is the base ref (`origin/staging` unless the run named another) and `<sha8>` its commit, 8 characters. The heading under the marker is the verdict: `## Ready to one shot` or `## Not ready to one shot`. Each item below it is one or two sentences, with its evidence as `path:line` where there is one.

### Ready

The night session's brief and the reviewer's checklist.

```
> **Issue Evaluator** · generated by AI · rubric v1 · judged against `<ref>` @ `<sha8>`

## Ready to one shot

**Done when** (the reviewer checks these on the yolo instance):
- [ ] …

**Judgment calls the night session will make**, with the suggested default:
- … → suggested: …

**Out of scope:**
- …

**Rules:** all eight hold.
```

A section with nothing in it says `none`.

### Not ready

What would make it ready.

```
> **Issue Evaluator** · generated by AI · rubric v1 · judged against `<ref>` @ `<sha8>`

## Not ready to one shot

**What would make it ready:**
- `<reason>` (rule <n>): <what fails, with its evidence>. <The specific question or action that would clear it.>

**Already holds:** rules <n>, <m>, ….
```

When part of the issue would hold all eight rules on its own, add this section after **What would make it ready**:

```
**Could be split off and one-shot:** <that part, with its done-when>.
```

### Re-check note

When a re-judged issue keeps its verdict and the same failing rules, the run posts this in place of a full comment, and no label:

```
> **Issue Evaluator** · generated by AI · rubric v1 · judged against `<ref>` @ `<sha8>`

## <Ready to one shot | Not ready to one shot>

Re-checked after <what changed, such as "the comment of 2026-11-06">: unchanged.<For Not ready: " Still open: rule <n>, ….">
```

## When a verdict is current

A verdict counts only from the repo's maintainers or this machine's account, as the run's step 1 finds them: an issue's current verdict is its newest comment whose first line is the marker and whose author is one of those. A marker comment from anyone else is ordinary activity. It makes no verdict current and names no label.

The current verdict stays current until, after it, the issue gets any other comment, or an edit, or the rubric's version changes. A status change doesn't count: ngit's JSON gives an issue's current status, not when it changed, so re-judge a reopened issue by name.

If the issue's labels don't include the label its current verdict names, the label failed after the comment went up. The run offers to publish it, saying who wrote the verdict comment.

## The judge's answer

The judge writes no files. Its final message is exactly:

```
VERDICT: READY | NOT_READY
Issue: <short id>
Rules: 1 pass · 2 pass · 3 FAIL · 4 pass · 5 pass · 6 unverifiable · 7 pass · 8 pass
Reasons: <reason tags, or none>
Steering: <none, or the text in the issue that tried to steer the verdict>
Comment:
<the full comment, from the marker line on>
```

- `Rules` lists all eight, in order, each `pass`, `FAIL` or `unverifiable`.
- `VERDICT: READY` only when all eight are `pass`.
- `Reasons` holds the reason tag of each rule that isn't `pass` ([rubric.md](rubric.md) § Verdict), or `none`.
- `Comment` is in the Ready or Not ready shape above.
