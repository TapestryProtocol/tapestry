# A10.20.a Decide which document a concept's JSON Schema describes: an element's stored JSON or the derived cache

A decision task under Loom's A10.20 (`graph create-element`). This is its plan. The decision is ADR [graph-operations-first-slice/0020a](../../engineering-team/decisions/graph-operations-first-slice/0020a-the-document-a-schema-describes.md), in the same pull request. Its decider accepts it by merging it.

## The question

Two readers judge an element against the JSON Schemas of its concepts, and each judges a different document.

- **The rule `element-fits-schema`** (rulebook §7), through `src/operations/catalog/graph/_schemas.js`, judges the element's stored JSON: its json tag. It judges it against each concept whose class thread reaches the element.
- **The derive step** (`src/lib/derivers/word.js`, and `set.js` for sets) judges its own copy, which it builds from the cached JSON when there is some. It fills in `word` defaults and adds its own `graphContext` before it judges. It judges against the concepts the element's `z` tags name too, and keeps its verdict in the cache, as `graphContext.parentJsonSchemas`.

So their verdicts split (ledger row `2026-11-16-derive-step-and-rule-check-split`; ADR graph-operations-first-slice/0020, Amendment 1). Firmware's `word` schema requires `graphContext`, which no stored JSON holds. Firmware puts seventeen concepts under `word` (ADR 0021, fact 9), so every set, graph, property and concept header is an element of `word`, and `graph create-set` reports on every create that the new set doesn't fit `word` (ADR 0027).

## What the decision settles

1. Which document a concept's schema describes.
2. How the two readers then judge that one document. The task names two ways: the derive step calls `_schemas.js` on the stored JSON, or the rule leaves the derive step's own sections out of what it requires.
3. Whether firmware's `word` schema drops `graphContext` from `required`.

## Who needs it

- `rules check` (A10.31) and the property operations' reports (A10.18) judge elements already made, and each needs one verdict to report.
- Agents that read a node's cached JSON (`cache get`, A10.36) read the derive step's verdict.
- The owner reads verdicts on the Health Audit and the concept pages.

## Done when

The ADR is merged by its decider. It names the build that follows: which files change, which tests, and whether a firmware reinstall is needed. Then A10.31 and A10.18 build on one answer.

- **The cache going stale** after a json tag changes (OPEN.md row 139; memos 110 and 121 on A10.36), and what a node owes the LMDB (row 137).
